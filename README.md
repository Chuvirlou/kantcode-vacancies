Что делает сервис

Для каждой вакансии оцениваются: название должности, обязанности, требования, оплата, график, место работы и тип занятости. Учитываются и текстовое описание, и структурированные поля API. Если поле содержит конкретные сведения, их отсутствие в описании проблемой не считается.

Сервис отмечает три вида замечаний:

Пропуск — нужных сведений нет нигде в вакансии;
Неоднозначность — формулировка не даёт конкретики (например, «гибкий график» без дней и смен);
Противоречие — в двух местах указаны разные значения одного параметра.

К каждому замечанию прилагается рекомендация, что именно уточнить. Сервис не выдумывает факты и не делает выводов о нарушении закона.

Два режима работы одним и тем же анализатором:

Режим	Команда	Источник данных
Рабочий	python -m app run	API региона 39, постранично
Проверочный	python -m app check <файл.json>	локальный JSON в формате ответа API, без обращения к порталу
Архитектура и пайплайн
API региона 39 ─┐
                ├─► loader ─► normalizer ─► rules (без ИИ) ─┐
локальный JSON ─┘                       └─► ai_check (LLM) ─┴─► merge + dedupe ─► report.json
Загрузка — app/fetcher.py, app/loader.py. Постраничный запрос API (offset — номер страницы, limit=100), повторные попытки с нарастающей паузой. Обрабатывается не менее двух страниц (MAX_PAGES=2 по умолчанию, если данных хватает). Остановка: пустая страница, MAX_PAGES или MAX_VACANCIES.
Нормализация — normalizer.py, models.py. Сырой JSON превращается в объект Vacancy: вложенные структуры (requirement, addresses, term, salary и т.д.) приводятся к плоским полям.
Правила — rules.py. Детерминированные проверки пропусков, размытых фраз и противоречий.
ИИ — app/ai_check.py. Локальная LLM ищет неконкретные формулировки и противоречия между полями (подробнее — в разделе Использование ИИ).
Сборка отчёта — app/pipeline.py, app/report.py. Замечания правил и ИИ объединяются, дедуплицируются по (topic, field, quote), отчёт пишется атомарно (временный файл + os.replace).
Что проверяется
Объект проверки	Примеры замечаний
Название должности	слишком общее или неинформативное название
Обязанности	поле пустое или формулировка без конкретики
Требования	пропуск; противоречие между требуемым опытом в разных полях
Оплата	не указана; вилка «от» больше «до»; разные суммы в полях и в тексте
График	не указан; «гибкий график», «по договорённости» без расписания; противоречие между полем графика и текстом
Место работы	не указан адрес; противоречие «удалённо» и «в офисе»
Тип занятости	пропуск; противоречие типа занятости и графика/сменности

Правило «конкретика где-то есть — проблемы нет»: если расписание, сумма или адрес указаны в структурированном поле, замечание о размытой формулировке в описании не создаётся.

Использование ИИ
Шаг пайплайна: этап 4, app/ai_check.py, функция analyze(vacancy). Результат ИИ входит в итоговый отчёт ("source": "ai").
Провайдер и способ запуска: локальная модель через Ollama, аккаунт и платные ключи не нужны.
Модель: qwen2.5:7b (меняется переменной AI_MODEL).
Что делает ИИ:
Находит формулировки без конкретики.
Находит противоречия между полями или между полем и текстом вакансии (обязательно приводятся обе цитаты).
Промпт: prompts/prompt_v3.md + дополнительные инструкции в ANALYSIS_INSTRUCTIONS.
Контроль качества ответа модели:
вывод по JSON-схеме (Pydantic, extra="forbid", до 5 замечаний на вакансию);
температура 0 и фиксированный seed — воспроизводимый результат;
цитаты проверяются локально: замечание принимается, только если цитата дословно присутствует в исходных данных вакансии (с нормализацией регистра, ё/е и пробелов);
рекомендации берутся из фиксированного набора, ИИ не придумывает факты и не оценивает законность условий.
Правила + ИИ: детерминированные правила ловят типовые случаи, ИИ — формулировки, которые заранее не перечислить.
Запуск проверочного режима с ИИ без аккаунта
bash
# 1. Установить Ollama: https://ollama.com/download (Linux: curl -fsSL https://ollama.com/install.sh | sh)
# 2. Запустить сервер и скачать модель (~4.7 ГБ)

Формат отчёта

Отчёт — JSON-массив, по одному объекту на каждую входную вакансию. Если замечаний нет, issues — пустой массив. Пример на учебных данных: data/report.example.json.

json
[
  {
    "id": "DEMO-39-002",
    "url": null,
    "issues": [
      {
        "topic": "Пропуск",
        "field": "salary",
        "quote": "",
        "problem": "Не указан размер оплаты.",
        "recommendation": "Укажите размер оплаты или диапазон",
        "source": "rule"
      },
      {
        "topic": "Неоднозначность",
        "field": "schedule",
        "quote": "Гибкий график",
        "problem": "Фраза «Гибкий график» не говорит, в какие дни и смены нужно работать.",
        "recommendation": "Уточните, в какие дни и смены нужно работать",
        "source": "rule"
      }
    ]
  }
]
Поля
Поле	Описание
id	идентификатор вакансии
url	ссылка на карточку вакансии (null, если нет)
issues	массив замечаний
topic	тема: Пропуск, Неоднозначность, Противоречие (для ИИ — «Формулировки без конкретики», «Противоречия между полями или между полем и текстом вакансии»)
field	поле источника, к которому относится замечание
quote	цитата или значение поля; для пропуска — пустая строка; для противоречия — обе исходные цитаты, разделённые /
problem	суть проблемы
recommendation	что именно нужно уточнить
source	rule — правило, ai — модель
Поведение при сбоях и повторных запусках
Идемпотентность: на каждый ID вакансии в отчёте ровно один объект; замечания дедуплицируются по (topic, field, quote). Повторный запуск на неизменных данных даёт тот же отчёт (температура ИИ 0, фиксированный seed).
API недоступен: после нескольких попыток выводится ошибка; сохраняется последний успешный отчёт (last_success.json), если он есть, и команда возвращает код 2, если его нет.
Запись отчёта атомарная — файл не остаётся повреждённым при сбое.
Сбой ИИ-шага логируется с ID вакансии.
